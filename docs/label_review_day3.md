# 동렬 담당 15개 라벨 검토 초안

대상: 최신 main `ef1a55d`의 `data/test_reviews.jsonl`.
범위: m01~m10, t06~t10. 원본 라벨은 수정하지 않았다.
이 문서는 AI 지원 검토 초안이다. 사람의 교차 검토 완료를 뜻하지 않는다.

| ID | 검토 결과 또는 확인할 점 |
|---|---|
| m01 | 설명의 명확성 → delivery 긍정. 이해가 된다는 표현만으로 learning을 추가할 필요는 낮음. |
| m02 | 수업 흥미와 집중 문제 → delivery 부정. |
| m03 | 커리큘럼·과제 피드백 → delivery 긍정. 학습 도움 → learning 긍정. |
| m04 | 음향 문제 → etc 부정. '강의 내용은 좋다'의 delivery 긍정은 구체성이 낮으므로 팀 검토 권장. |
| m05 | 과제 부담을 비꼬는 표현 → workload 부정. |
| m06 | '학점을 테라피 받는 기분'을 grade 긍정으로 보는 해석 확인. 명강 부정 → learning 부정. |
| m07 | 시간·비용 아쉬움 → 총평 부정. 자기자랑 → professor 부정. summary는 정제 필요. |
| m08 | 학생 응대 태도 → professor 부정. 기분 표현을 별도 총평으로 중복 추출할지 검토. |
| m09 | 출석·과제 사실 나열 → attendance·workload 중립. |
| m10 | 자료를 사용하는 방식 설명 → delivery 중립. 불만을 추론하지 않음. |
| t06 | 교수자 응대 부정 / 학습 유익 긍정 / 재수강 의사 부정. summary 정제 확인. |
| t07 | 총평 긍정 / 선수지식 조건의 delivery 부정 / 조교 지원 etc 긍정. condition 의미 확인. |
| t08 | 시험 종류 사실은 exam 중립, 학습 부담은 workload 부정. 단, '시험 횟수'는 workload라는 가이드와의 경계를 확인. 변경 언급 true를 보존. |
| t09 | 과제 힌트를 workload 긍정으로 지정한 라벨은 '과제 피드백=delivery'와 경계가 있음. '고생'의 workload 부정도 문맥 확인 필요. 성적 미정은 추출하지 않음. |
| t10 | 기존 후기 반박 속 학점 불만 → grade 부정. '할많하않'은 맥락상 총평 부정으로 검토. |

45개 모두 ID 중복, category·sentiment enum, 근거의 원문 포함 여부를 검사했다.
이 구조 검사는 라벨 의미의 정확성을 보장하지 않는다.

사람 검토 완료 확인 전에는 45개 결과를 '제공된 1차 라벨 대비 잠정 평가'로 기록한다.
프롬프트 수정 시 위 라벨을 점수에 맞춰 임의 변경하거나 테스트 문장을 few-shot에 추가하지 않는다.
