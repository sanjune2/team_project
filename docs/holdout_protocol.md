# 신규 holdout의 첫 평가 절차

`data/holdout_reviews.jsonl`은 이번에 새로 작성한 가상 강의평 20개다.
기존 후보 10개와는 다른 파일이다. 원본 45개를 대체하지 않는다.
동결 시각·내용 해시·평가할 v2 프롬프트 해시는 `data/holdout_reviews_manifest.json`에 기록했다.
두 분리 데이터 파일은 `.gitattributes`에서 LF 줄바꿈으로 고정한다. 운영체제가 달라도 동결 해시를 보존한다.

## 현재 상태

- 원문 20개, 정답 item 22개. 10개 category를 모두 포함한다.
- 단일 10개 / 중립 3개 / 혼합 3개 / 반어 2개 / 평가 없음 2개.
- AI 지원 합성 초안이며 사람의 독립 라벨 검토는 미완료다.
- 이 파일로 평가 대상 모델을 호출한 횟수는 0회다. 정확도는 아직 측정하지 않았다.
- 기존 45개·로컬 29개·smoke·재사용 후보와 ID 및 정규화 원문 완전 중복은 없다.
- 문자 유사도 검사도 수행했다. 이 검사가 의미적 독립성이나 학습 데이터 미포함을 보장하지는 않는다.
- 이 파일을 이용해 프롬프트를 수정하거나 few-shot을 추가하지 않았다.

## 첫 측정 전

1. 예측 결과를 보지 않은 팀원이 category·sentiment·evidence·condition·mentions_change를 검토한다.
2. AI 초안의 수정과 합의 내용을 남긴다. 수정 후 새 데이터 해시를 다시 동결한다.
3. 평가할 모델·프롬프트·사전·스키마·추론 설정·샘플링·timeout·retry를 고정한다.
4. 새 문장을 프롬프트 개발에 쓰지 않은 상태에서 첫 평가를 1회 진행한다.
5. 기존 45개 점수와 새 20개 점수를 분리해 보고한다. 실패·제외 수와 분모를 함께 쓴다.

이 절차를 지킨 첫 측정은 **동결한 v2에 이번 신규 20개를 처음 입력한 결과**로 기록할 수 있다.
서비스 이용자 전체를 대표하는 실사용 정확도나 모델 학습에서 완전히 배제된 데이터라고 주장하지 않는다.
사람 정답 확정 전에는 새 AI 초안 라벨 대비 잠정 수치로만 기록한다.

## 첫 측정 후

오답을 보고 프롬프트를 고치면 해당 20개는 이후 개발 데이터가 된다.
추가 수정의 일반화 성능을 확인하려면 새로운 미사용 데이터가 필요하다.
점수를 올리려고 정답을 바꾸지 않는다. 라벨 오류 정정은 이유와 전후 해시를 별도로 남긴다.

## 실행 주의

현재 `python -m analysis.evaluate` CLI는 45개 고정 검사다.
이 20개를 실행하려고 복제해 45개로 만들거나 기존 테스트셋에 섞지 않는다.
별도 20개 분모의 실행기를 팀과 확인한 뒤 사용한다.
평가 함수 `evaluate(gold, predictions)` 자체는 리뷰 수에 독립적이지만, 이 PR은 holdout 실제 평가를 수행하지 않는다.

기존 재사용 후보의 노출 이력은 `docs/local_review_candidates.md`를 확인한다.
