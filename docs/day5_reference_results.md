# 5일 차 레퍼런스 가상 강의평 64개·실제 분석 결과

## 결과

- 가상 교수 2명 × 과목 2개 × 학기 2개 × 리뷰 8개 = 64개다.
- p01 김가나: c01 데이터분석 기초 / c02 파이썬 프로그래밍.
- p02 이다라: c03 경영통계 / c04 마케팅원론. 학기는 모두 2025-2 / 2026-1이다.
- 2026-10-24 실제 `/api/analyze` 실행에서 **64개 성공·실패 0개**를 확인했다.
- `frontend/public/reference/`에 학기 파일 8개 + 과목 합산 4개 + `index.json`을 저장했다.
- Notion 완료 기준 ②의 데이터 결과를 제출한다. 화면 기준 ①과 실제 연결 기준 ③은 아직 검증하지 않았다.

출처: [5일 차 체크리스트](https://app.notion.com/p/5b4ab1969cf58337b2f00162019ba716). 실행 기준 main은 `3e357ff2eba65d28b747f3fe3c16dbbcb815238c` (#18 병합)다.

## 실행과 검증

- Python 3.14.0 / OpenAI 2.54.0 / Pydantic 2.14.1. 기존 unittest 24개 통과.
- `USE_MOCK=false`, `OPENAI_MODEL=gpt-6-luna`, reasoning `none`, temperature `0`, timeout 30초, SDK retry 0이다. 키는 기존 비공개 환경에서 읽었으며 복사·출력하지 않았다.
- #18의 생성 스크립트와 현재 백엔드를 그대로 사용했다. API 계약·운영 프롬프트·백엔드·프런트엔드 코드는 변경하지 않았다.
- 최종 학기 파일 8개를 `AnalyzeResponse`로 검증했다. 64개 모두 ID·학기·원문·순서를 보존했다.
- 최종 248개 분석 항목의 근거가 모두 원문의 부분 문자열이다(`evidence_match=exact`, `evidence_verified=true`). 이는 **분류 정확도 100%라는 뜻이 아니다**.
- 각 묶음 r02 잡담 8개는 모두 `items=[]`, `overall_sentiment=null`, `status=ok`다.
- 합산 파일은 학기별 저장 결과를 재사용했다. LLM 재호출 없이 `summarize_by_category()`로 집계했고 재계산 결과가 일치한다.
- index의 학기·합산 파일 12개 참조가 모두 존재한다.
- p02 도착 전 p01 32개를 먼저 분석했다. 이후 Notion 지시대로 두 입력을 함께 넣어 64개를 다시 실행했다. 이번 작업의 분석 대상 호출 수는 총 96개다. 최종 파일은 두 번째 실행 결과다.

## 혜린 담당 화면 연결

목록 경로는 `/reference/index.json`이다. `professors[].courses[]`는 학기 파일을, `courses[]`는 과목 합산 파일을 가리킨다.

- 교수자 예: `/reference/c01_2025-2.json` (리뷰 8개).
- 학습자 예: `/reference/c01_all.json` (두 학기 리뷰 16개).
- 나머지 과목도 c02/c03/c04로 같은 규칙을 사용한다.

각 파일은 #18 샘플과 같이 API 응답에 `reviews[].text`만 추가한 형식이다. 새 종합 요약 화면의 첫 연결은 학기 파일 하나로 진행할 수 있다. 실제 화면의 TOP 3·항목 클릭·긴 글 줄바꿈은 프런트엔드 작업 후 확인해야 한다.

이 데이터는 시연용 합성 데이터다. 독립 평가셋이나 실제 고객 분석 결과로 사용하지 않는다. 원문 근거 검증과 별개로 항목 경계 오류가 있을 수 있다. 당일 프롬프트 수정 금지 조건에 따라 출력 내용을 손으로 고치지 않았다.

최종 출력의 후속 검토 사례: `c01-2026-1-r06`의 마이크 끊김이 가이드의 `delivery` 대신 `etc`로 분류됐다. `c02-2025-2-r07`의 조별 발표 없음이 전자출결과 함께 `attendance` 요약에 포함됐다. 화면 샘플 검수에 참고하며 분류 개선은 별도 작업으로 남긴다.

## 재현 명령

실제 LLM 환경을 설정하고 서버를 켠 뒤 저장소 루트에서 실행한다.

```powershell
uvicorn backend.main:app --port 8000
```

다른 터미널:

```powershell
python scripts/build_reference_data.py --input data/reference/reviews_p01.jsonl data/reference/reviews_p02.jsonl
```

이 명령은 실제 LLM을 다시 호출하고 파일을 덮어쓴다. 이미 저장된 JSON을 화면에서 읽는 데 재실행은 필요하지 않다. p02만 지정하면 index에서 p01이 빠지므로 두 입력을 함께 사용한다.
