# 디자인 가이드

화면을 만들거나 고칠 때 이 문서를 먼저 따릅니다. AI 코딩 도구에도 이 문서를 그대로 전달합니다.

## 0. 전제

- 이 화면은 고객사(학사 시스템) 페이지 안에 들어가는 결과 화면입니다. 튀지 않고 정보만 또렷하게 보여야 합니다.
- 방향: 흰 배경, 진한 회색 글자, 얇은 선, 의미에만 쓰는 색 (Editorial × Data Minimalism)
- 색·글자·간격 값은 `src/styles/tokens.css`의 변수만 씁니다. 컴포넌트에 색상 코드나 px 글자 크기를 직접 쓰지 않습니다.
- 토큰 값은 v0입니다. 레퍼런스가 정해지면 **변수 값만** 바꾸고, 컴포넌트는 고치지 않습니다.

## 1. 반드시 지킬 규칙

1. 문구의 구분자로 가운뎃점 `·`을 쓰지 않습니다. 있으면 지우고, 간격이나 줄바꿈으로 나눕니다.
2. 불필요한 설명 문구를 넣지 않습니다. 화면을 지저분하게 하고 주의를 낭비합니다.
3. 문구는 대상(교수자·학습자)에 맞게 씁니다. 이해하기 쉽되 지나친 구어체는 피하고, 기능에 맞는 길이로, 임의로 만든 단어는 쓰지 않습니다.
4. 모든 색은 Radix UI Colors에서 가져오고, 그 사용 규범을 따릅니다. (1~2 배경 / 3~5 요소 배경 / 6~8 선 / 9~10 진한 색 / 11~12 글자)
5. 요소는 광학적으로 정렬합니다. 겹치는 부분이 있으면 동심원 모서리로 처리합니다 (안쪽 반지름 = 바깥 반지름 − 안쪽 여백).
6. 선·테두리가 필요하면 0.5px로 씁니다 (`--border`).
7. 애니메이션·전환은 최대한 줄입니다. 꼭 필요하면 `ease-out`, 250ms를 기본으로 씁니다.
8. 글자 크기는 4종을 넘기지 않고, 3종이 가장 좋습니다. 최소 크기는 12px입니다. 부족한 위계는 굵기, 색, 간격으로 만듭니다.
9. 사용자가 판단해야만 넘어갈 수 있는 상호작용을 최소화합니다. 꼭 필요하면 사용자가 이미 선택하려는 자리에 둡니다. 기능과 요소의 우선순위를 다시 따져 질서 있게 배치합니다.
10. 둥근 모서리와 그림자를 무작정 쓰지 않습니다. 특히 카드 왼쪽 가장자리에 색 선을 넣지 않습니다. 꼭 써야 하면 기능에 맞게 값을 정합니다.
11. Eyebrow(제목 위 작은 머리말)와 Overline(제목 위 작은 태그)을 줄입니다. 영어 대문자 소제목을 습관적으로 붙이지 않습니다. 제목에 없는 분류·맥락·핵심 정보를 줄 때만 둡니다. 위계는 글자 크기·굵기·간격·여백으로 만듭니다.
12. 불필요한 보조 레이블과 설명을 피합니다. 레이아웃이 설명하게 합니다.

## 2. 추가로 하지 않는 것

- 카드로 감싸기, 카드 안의 카드, 벤토 그리드, KPI 카드 나열
- 그라데이션, 유리 효과, 장식용 아이콘·이모지·일러스트
- 알약 모양 버튼·뱃지

- 디자인 수정과 데이터·API 로직 수정을 한 커밋에 섞기
- 필요 없는 UI 라이브러리 추가 (색은 `@radix-ui/colors`만 사용)
- 모델명, 처리 시각 등 사용자에게 필요 없는 기술 정보 노출

## 3. 접근성과 안정성

- 만족·불만족을 색으로만 구분하지 않습니다. 단 제목, 위치, 숫자 글자로도 구분되게 합니다.
- 사용자의 모션 줄이기 설정(`prefers-reduced-motion`)을 따릅니다. (`tokens.css`에 반영)
- 0.5px 선은 화면에 따라 1px로 보이거나 흐릴 수 있습니다. 일반 모니터와 노트북 화면에서 한 번씩 확인합니다.
- 리뷰·요약 길이가 달라져도 정렬이 무너지지 않게 합니다. 긴 단어·URL은 줄바꿈되게 하고(`overflow-wrap: anywhere`), 요약노트는 줄 수를 제한합니다.
- 좁은 화면(640px 미만)에서도 정보 순서가 같게 유지됩니다.

## 4. 토큰 요약 (`src/styles/tokens.css`)

| 구분 | 값 |
| --- | --- |
| 배경 | `--bg` gray-1, `--bg-subtle` gray-2, `--bg-hover` gray-3 |
| 선 | `--line` gray-6, `--border` 0.5px |
| 글자 | `--text` gray-12, `--text-sub` gray-11 |
| 만족 | `--pos` green-11 (글자), `--pos-solid` green-9 (막대), `--pos-bg` green-3 |
| 불만족 | `--neg` red-11, `--neg-solid` red-9, `--neg-bg` red-3 |
| 중립 | `--neu` gray-11, `--neu-solid` gray-8 |
| 글자 크기 | `--fs-title` 20px / `--fs-body` 15px / `--fs-small` 13px |
| 굵기 | 400 / 600 |
| 간격 | 4 / 8 / 12 / 16 / 24 / 32 / 48px (`--sp-1`~`--sp-7`) |
| 모서리 | 기본 0, 버튼·입력창 2px |
| 움직임 | 기본 없음, 필요 시 250ms ease-out |

## 5. 이 서비스 화면에 적용하면

- 종합 요약: 만족 │ 불만족 2단 (좁은 화면에서는 1단). 각 단은 순위 목록이고 카드로 감싸지 않습니다.
- 순위 항목: 항목명(본문 크기, 굵게) + 리뷰 수(작은 크기, 숫자 폭 고정) + 요약노트(본문 크기, 보조 색)
- 만족·불만족 구분은 색 선이 아니라 단 제목과 글자 색으로 합니다.
- 비율: 높이 6px 가로 막대 하나 (만족·불만족·중립 순), 숫자는 막대 옆 글자로. 축·격자·범례 없음
- 과목 정보: 제목 한 줄 + 학기·리뷰 수 한 줄 (가운뎃점 없이 간격으로 구분)
- 숫자에는 `.num` 클래스를 붙입니다.
- 모델명, 처리 시각 같은 개발용 정보는 화면에 넣지 않습니다.

## 6. AI 코딩 도구 작업 순서

1. 화면의 목적과 첫 화면에 꼭 필요한 정보를 먼저 정합니다.
2. 기존 화면에서 규칙에 어긋나거나 불필요한 요소를 찾습니다.
3. 데이터 구조와 API 호출은 그대로 두고 정보 위계만 다시 짭니다.
4. 새 요소를 넣기 전에 기능상 이유가 있는지 확인합니다.
5. 작업 후 아래 PR 전 확인 목록을 점검합니다.
